## Hyprland Lua gotchas

- With Lua config, legacy `hyprctl dispatch <name> <args>` often fails (parsed as invalid Lua).
- Prefer: `hyprctl eval 'hl.dispatch(hl.dsp....)'`
- Scratch special-workspace toggle:

```bash
hyprctl eval 'hl.dispatch(hl.dsp.workspace.toggle_special("scratchterm"))'
# or scratchmath
```

- Reload config without killing the session: `hyprctl reload` (when that is enough).
- App launcher (sxhkd Super+D): `~/.Scripts/fuzzel_drun` (Wayland fuzzel + wal colors). Old X11 path: `dmenu_drun`.
- Fuzzel rice: centered, radius 10 / border color4 (like dunst), translucent color0 (`cc`) + `layer_rule` blur on namespace `launcher`. Regenerates `~/.config/fuzzel/fuzzel.ini` each launch.
- Gotcha: don’t `source` full `~/.cache/wal/colors.sh` under `set -u` — it expands unset `FZF_DEFAULT_OPTS` and aborts. `fuzzel_drun` greps `colorN=` only. Also `exit-on-keyboard-focus-loss=no` so Super release doesn’t kill the launcher.

## Dotfiles sync (`dot`)

Bare-repo git wrapper for tracked configs under `$HOME` (not a normal repo in `~`). Use this when the user asks to sync / commit / push machine config changes.

| Piece | Path |
|-------|------|
| Wrapper | `~/.Scripts/dot` |
| Bare git dir | `~/.dotfiles` |
| Work tree | `$HOME` |
| Remote | `git@github.com:The3File/dots.git` (`origin`, branch `master`) |

**Equivalent:** `git --git-dir="$HOME/.dotfiles" --work-tree="$HOME" …`

**Commands (via `dot …`):**
- `dot status` / `dot diff` / `dot log` — inspect (any git subcommand works)
- `dot add <paths>` — stage; **required for new files** (`status.showUntrackedFiles = no`, so untracked stay invisible until added)
- `dot up [message]` — if dirty: `commit -am` (default message = porcelain status lines), then `push`. Optional message replaces the default.
- `dot pull` — pull from origin
- Plain `dot commit …` / `dot push` also fine; prefer `dot up` when the user says “synkroniser”

**README dance:** before commit, script copies `~/.dotfiles/README.md` → `~/README.md`, stages it, commits; after the command it moves README back into the bare repo and `assume-unchanged`’s `~/README.md` so it doesn’t clutter the home tree. Don’t fight that.

**Agent habits:**
- Sync **machine/dotfile** changes with `dot`, not `git` in a random project repo, and not by inventing a second dots workflow.
- Only sync when the user asks (same rule as normal commits). Summarize what will be included first if unclear.
- New paths (e.g. new `~/.Scripts/…`) must be `dot add`’ed once; afterwards `dot up`’s `commit -am` picks up modifications to tracked files.
- `~/CONTEXT.md` **is** tracked in the dots repo — keep it updated and include it in syncs when the user asks.
- Repo tracks selected files only (~180); includes `.Scripts/`, Hyprland/alacritty/waybar, etc. Do not bulk-add secrets (keys, tokens, full browser profiles). Skip large local model blobs (Whisper/Piper voices under `~/.local/share/`).

Install from scratch (user docs): `curl` of `.install.bash` from the `dots` repo — see `~/.dotfiles/README.md`.
